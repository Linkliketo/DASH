## 一、身体动捕路线（视频 → 3D 骨骼动画 BVH）

### 路线总览矩阵

| 编号 | 路线 | 核心链条 | 状态（已核查） | GPU/CPU | 开源 |
|------|------|---------|------|---------|------|
| **V0** | **快速验证组合（零成本冒烟测试）** | SysMocap（GUI 全身动捕）+ facial-motion-capture（浏览器面部 BlendShape）→ 引擎内双源合并 | 现成产品级工具，免环境配置 | 纯 CPU，本地即可 | ✅（license 待确认⏳） |
| **B1** | 三段式基线（DASH 原案） | MediaPipe Holistic → Kalman3D → SMPL-X L-BFGS 拟合 → BVH | 全部组件可得 | CPU 可跑（拟合环节存疑） | ✅ |
| **B2** | 单模型 HMR 回归 | ViT 单模型 → SMPL/SMPL-X 参数 → 关节旋转 → BVH | Multi-HMR / Multi-HMR2 / TokenHMR / OSX 均有官方代码+权重 ✅ | **需 GPU**（跑通首选之一） | ✅ |
| **B3** | **PEAR 单模型（已开源！）** | ViT-B → EHM-s（SMPL-X+FLAME 联合）→ BVH + 表情 | ✅ **github.com/Pixel-Talk/PEAR 已发布**，权重自动下载 | 需 GPU（3090 实测 28–43 FPS） | ✅ |
| **B4** | MocapNET v4.0 | MediaPipe/OpenPose 2D → NSRM + 朝向分类 SNN → BVH | GitHub 可 clone，30Hz 笔记本实测 | CPU 可跑 | ✅ GPL ⚠️ |
| **B5** | 经典 2D→3D lifting 管线 | MediaPipe/OpenPose 2D → VideoPose3D → BVH | video2bvh（MIT）等现成仓库 | CPU 可跑 | ✅ ⚠️ OpenPose 非商用 |
| **B6** | MoCapAnything（任意骨骼） | 参考骨骼 prompt + 视频特征 → 轻量 IK → 任意骨骼 BVH | ✅ **已开源**：github.com/phongdaot/MocapAnything，HF 权重 + 在线 demo，V2 已发布 | GPU 建议 | ✅ |

### 各路线详述

#### V0 快速验证组合（P1 第 1 周第一步，来源：项目根目录 `testRoad.md`）

- **组成**：SysMocap（github.com/xianfei/SysMocap，MediaPipe 底子，GUI 开箱即用，支持 VRM/FBX/GLB 拖入、转发 OBS/Unity/Unreal/WebXR）+ facial-motion-capture（github.com/PooyaDeperson/facial-motion-capture，纯浏览器运行，landmark→BlendShape，可录 GLB 导出）。
- **定位**：所有路线中上手成本最低的**端到端冒烟测试**——不装 Python、不需 GPU，半天内看到“摄像头→虚拟角色”完整画面。
- **对 DASH 的独特价值**：① 第 1 周即可预演 S4 引擎桥接链路（OSC/WebSocket 转发到 Unity/Unreal），把原本 P3 的集成风险提前暴露；② “身体一路+面部一路、引擎内合并”与 DASH 双通道设计同构，等于系统集成模式的免费预演。
- **边界**：无 SMPL-X 拟合/Kalman/AU 语义/BVH 导出，**不能做研究级精度评估，不进论文对比表**；仅用于概念验证、引擎链路预演、团队演示素材。

#### B1 三段式基线（申报书方案，必须实现）

```
Camera → MediaPipe Holistic (543 kpts, ~16ms, CPU可)
       → Kalman3D 逐点滤波 (~1ms)
       → SMPL-X L-BFGS 拟合 (⚠️ 15ms 数字存疑，需实测)
       → 24 关节旋转 → BVH
```

- **角色**：创新叙事主干 + 所有路线的对比基准。无论最终采用哪条路线，B1 都必须跑通——论文消融需要它。
- **核心风险**：SMPL-X 逐帧迭代优化在 CPU 上大概率是秒级（PROMPT.md 风险 #1）。**降级预案**：① 降迭代数 + warm-start；② 只拟合 24 关节旋转不拟合形状；③ 轻量 2D→3D lifting NN（B5）替代拟合；④ **GPU 上跑拟合（云 GPU 前提下最直接）**。
- **资源**：MediaPipe（pip 即得）；SMPL-X 模型需 MPI 官网学术注册下载 ✅（smpl-x.is.tue.mpg.de）。

#### B2 单模型 HMR 回归（跑通首选之一）

一次前向直接从图像回归 SMPL-X 参数，省掉关键点检测+滤波+拟合三段。

| 候选 | 出处 | 输出 | 代码/权重（已核查） | 备注 |
|------|------|------|----------|------|
| **Multi-HMR** | ECCV 2024 (NAVER) | SMPL-X 全身+手+面，**支持多人** | ✅ github.com/naver/multi-hmr，代码+checkpoint，研究 license | ViT-S 448² 快速版 / ViT-L 896² 精度版 |
| **Multi-HMR2** | 2025–26 (NAVER) | 同上（更新版） | ✅ github.com/naver/multi-hmr2，**权重首次推理自动下载** | 新发现，优先试这个 |
| **TokenHMR** | CVPR 2024 (MPI) | SMPL（无面/手） | ✅ github.com/saidwivedi/TokenHMR | tokenized 姿态表示 |
| **OSX** | ICCV 2023 (IDEA) | SMPL-X 全身 | ✅ 官方开源 | PEAR 同机构前作 |

- **关键事实**：SMPL-X 参数 → BVH 是确定性转换（24 关节轴角 → 欧拉 ZXY → BVH MOTION 段），无需训练。
- **风险**：面/手精度不如 PEAR；license 为研究用途（§5.1）。

#### B3 PEAR（★ 已开源，升为一级候选）

> **v1.1 重大更新**：PEAR 代码与推理管线已发布（github.com/Pixel-Talk/PEAR）。核查确认：
> - 预训练模型**首次推理自动下载**；图像/视频推理脚本齐备（`inference_images.py` / `app.py`）
> - 需自备 **FLAME / SMPL / SMPL-X 模型资产**（MPI 注册下载，放入 `assets/`）
> - 训练数据**未完整公开**（仅提供示例 tar）→ 复现训练不可行，但推理+微调可行
> - 项目页数据集仍标注 coming soon

- 唯一同时回归 SMPL-X + FLAME 且达 SOTA 的方案（3DPW MPJPE 71.3，面部 LVE 1.22，3090 上 28–43 FPS）。
- **原决策门 G1 的"开源"条件已满足**，剩余条件：GPU 到位（云租赁已解决）+ FLAME→BlendShape 映射验证（P2-1）。**建议：P1 即将 PEAR 跑通纳入计划**，与 B2 共用 SMPL-X→BVH 转换器。
- 阻塞点（新）：训练数据不全 → 若需领域微调，只能用伪标签策略或自采数据做小范围 fine-tune。

#### B4 MocapNET v4.0（baseline + BVH 格式验证工具）

- 与 DASH 目标最接近的现成开源系统（2D → BVH，30Hz，含身体+手+面部 landmarks）。
- **用途**：① P4 对比 baseline；② 交叉验证 DASH 自写 BVH 导出器格式正确性。
- **⚠️ GPL license**：只做外部对比，**代码不进 DASH 仓库**。

#### B5 经典 lifting 管线（最快可见 demo）

- video2bvh（MIT，655 stars）：OpenPose 2D + VideoPose3D → BVH，含 Blender 重定向教程。
- **用途**：P1 第一周跑通的"端到端存在感"demo；VideoPose3D 时序卷积天然抗抖，可作 B1 拟合环节的降级备件。
- **⚠️ OpenPose 为 CMU 非商用 license**；用 MediaPipe 2D 输出替代即可规避。

#### B6 MoCapAnything（已开源，观望→可试用）

> **v1.1 更新**：已确认开源——github.com/phongdaot/MocapAnything（SIGGRAPH Asia 2026 版本为 V2），HuggingFace 权重 + 在线 demo 可用。

- 任意骨骼拓扑 BVH + 轻量 IK，直接命中"游戏角色骨骼 ≠ SMPL-X 24 关节"的重定向问题。
- **用途**：S4 引擎集成阶段的角色重定向备选；P1 可用在线 demo 零成本验证效果。

## 二、面部表情路线（面部区域 → AU / BlendShape）

### 路线总览矩阵

| 编号 | 路线 | 核心链条 | 状态（已核查） | GPU/CPU | 开源 |
|------|------|---------|------|---------|------|
| **F1** | LibreFace → AU → 映射（DASH 原案） | ResNet-18 → 17 AU 强度 → RBF/MLP → 52 BlendShape | ✅ github.com/ihp-lab/LibreFace（USC research license，2.0 分支活跃） | CPU 可跑，GPU 更快 | ✅ |
| **F2** | OpenFace 3.0 多任务 | 单模型 → landmark + AU + 视线 + 表情 | ✅ github.com/CMU-MultiComp-Lab/OpenFace-3.0，研究免费，一行安装 | 实时 | ✅ |
| **F3** | 仅 landmark 轻量 AU 网络 | MediaPipe 468 点 → 数千参数 NN → AU | PMC11851526，需自行复现 | CPU 极快 | ⚠️ 论文有，代码未见官方发布 |
| **F4** | FLAME 直接回归（EMOCA/SMIRK） | 图像 → FLAME 表情参数 → MLP → 52 BlendShape | ✅ 官方代码（emoca / smirks），MPI 研究 license | **GPU 友好** | ✅ |
| **F5** | PEAR 内含 FLAME（随 B3） | EHM-s φ_h (50D) → MLP → 52 BlendShape | ✅ 随 B3 解除阻塞 | GPU | ✅ |

### 各路线详述

#### F1 LibreFace + 映射（DASH 选型，主干）

- **优势**：语义化 AU 输出是 DASH 相对 PEAR/MetaHuman 的差异化卖点（可解释、可编辑、可映射任意 BlendShape 体系）；22.5M 参数是 S3 量化/剪枝的理想对象。
- **License（已核查）**：USC research license——研究可用，商用需另行授权，论文/开源场景无碍。
- **两个实现变体**：RBF 无训练映射（零数据，立即可用）vs MLP 可学习映射（需配对数据 → 任务 P2-1 合成数据流程）。
- **升级路径**：LibreFace 2.0（FG 2026）分支在官方仓库活跃开发中，跟进成本低。

#### F2 OpenFace 3.0（对照组）

- ✅ 已核查：CMU-MultiComp-Lab/OpenFace-3.0 公开发布，研究用途免费，一行命令安装运行。
- **用途**：与 F1 做 AU 精度/速度对照（BP4D F1、DISFA PCC），丰富论文对比表格。

#### F3 仅 landmark 轻量 AU 网络（极限轻量化王牌）

- 输入复用 MediaPipe 已有 468 点，**无需额外图像推理**，数千参数。
- **价值**：P4"极限压缩"消融的王牌（22.5M → <0.01M）；远期 CPU 实时的关键拼图。
- **风险**：未见官方代码，需自行复现（1–2 周），AU 定义需对齐 LibreFace 输出。

#### F4 EMOCA/SMIRK FLAME 回归（GPU 高质量路线）

- 直接回归 FLAME 表情参数（EMOCA 50D），几何精度高于 AU 间接路线。
- **定位**：F1 为主、F4 为精度上界对照；若身体走 B3(PEAR)，则面部同源 FLAME（F5），保持同一参数化体系。
- **License**：EMOCA/SMIRK/FLAME 均为 MPI 学术研究 license，需注册。

#### F5 随 B3 决策门处理（B3 开源后可行性同步解除）。

### AU→BlendShape 映射专项（所有面部路线的公共出口）

| 方案 | 训练 | 数据 | 出处参考 | 精度 |
|------|------|------|---------|------|
| RBF (Multiquadric) | 无 | 手工锚点 | DASH 原案 | 基线 |
| KNN / Ridge | 极少 | 配对样本 | Gaussian Head Avatars (2025) | 中 |
| **MLP** | 需训练 | 合成配对（P2-1）或 **Express4D（已确认开源 ✅）** | 同上 | 高（推荐） |

> **v1.1 更新**：Express4D（github.com/jaron1990/Express4D）已确认可用——1205 序列、61 维 ARKit 向量（52 BlendShape + 9 旋转）、60Hz、带文本情绪标签。**AU→BlendShape 配对数据的最大缺口有了真实数据兜底**，合成数据流程（P2-1）从"必需"降级为"增强"。

### 4.5 云端成本控制策略（v1.1 新增）

> 云 GPU 平台（AutoDL 类）计费特征：① 实例**按量计费、关机即停 GPU 费**（数据通常保留有限天数，如 15 天）；② **数据盘/文件存储独立弹性计费**。

**成本控制五条原则：**

1. **实验完即关机/释放实例**，GPU 费用归零；需要长期保留的只有数据和镜像。
2. **分层存储**：代码+环境 → 系统盘镜像；模型权重+常用数据集 → 数据盘（按 §4.4 最小集 ~35 GB 起步，按需扩容）；大体积原始数据集（H36M 视频、BP4D）→ **处理完立即提取特征/标注并删除原始文件**，只留处理结果（通常可压缩 10–50 倍）。
3. **下载在云实例内完成**（云平台到各数据集官网的带宽通常远好于本地），避免本地上传。
4. **先小后大**：P1 只备最小集；确认路线后再申请/下载推荐集，避免为弃用路线付存储费。
5. **免费额度优先**：跑通/调参/小规模评估类任务优先放免费平台（§4.6），付费算力只用于渲染、批量推理、训练等重任务。

### 5.3 已知坑（文献已确认）

1. **SMPL-X L-BFGS 拟合 CPU 不现实**（PROMPT 风险 #1）→ P1 第一周实测；云 GPU 可作直接预案。
2. **INT8 ONNX CPU 可能反而更慢**（onnx#6030）→ P2 之后的事，不阻塞。
3. **MediaPipe z 坐标是相对深度非真实尺度** → 不能拿 543 点直接当 3D GT。
4. **MediaPipe 手部 ROI 非理想角度精度下降**（Moryossef 2024，有公开修复方案）。
5. **PEAR/FLAME 输出是 50D 表情参数不是 ARKit 52D** → 必须过 MLP 映射（F4/F5 共用，Express4D 可提供训练数据）。
6. **坐标系/旋转序**：SMPL-X 轴角 → BVH 欧拉 ZXY；Unity 左手 Y-up vs CV 管线右手系 → BVH 导出器内置转换开关 + 单测（用 MocapNET 输出交叉验证）。
7. **PEAR 训练数据未完整公开** → 只能推理或基于其伪标签策略微调，无法从头复现训练。

| 规则 | 内容 |
|------|------|
| 参评路线 | B3 PEAR、B2 Multi-HMR2、（可选 OSX）+ B1 基线 |
