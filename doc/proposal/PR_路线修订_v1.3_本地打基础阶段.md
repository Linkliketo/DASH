## 一、修订要点

v1.2 的 P1 前提是"云 GPU 到手 → 跑通大模型"。实际执行改为：**先在本地 CPU 上，用 MediaPipe 的 TFLite 模型打通量化工具链与方法论**；云阶段整体后移，云预算（¥800–1,600）**分文未动**。

连带三处调整：

| 调整 | 内容 |
|---|---|
| **S3 量化对象分两批** | 第一批 MediaPipe TFLite（练工具链）；第二批 LibreFace ResNet-18（v1.2 原定目标） |
| **面部路径分两车道** | 快车道：MediaPipe → 52 BlendShape（打通链路）；叙事车道：LibreFace → 17 AU → RBF/MLP（差异化卖点） |
| **新增候选 B** | 自产 `(landmarks → blendshapes)` 数据集 + 训练小网络，覆盖 TFLite→ONNX 转换失败的模型 |

**v1.2 中尚未执行的部分（B1–B6 / F1–F5 / 云算力 / 数据集注册）全部保留，只是排到了后续阶段。**

## 三、已完成部分的技术发现

以下 7 条是本地阶段实际测出来的，可直接写进技术报告或作为面试素材：

| # | 发现 | 来源 |
|---|---|---|
| 1 | `.task` 是**零压缩的 ZIP 容器**，内含 3 个独立 `.tflite` + 1 份几何元数据（尺寸自校验完全吻合） | Task 3 |
| 2 | `tflite2onnx` 对 3 个模型**只有 1 个可用**；失败原因是转换器内部 bug（`TypeError` / `IndexError`），**不是算子不支持** | Task 4 |
| 3 | TFLite 用 **NHWC**、ONNX 用 **NCHW**；对比时同一份数据须按两种 layout 分别喂入 | Task 4 |
| 4 | 转换误差 ~1e-4 来自模型内部 **float16**，非转换逻辑 → 量化对比必须**同侧进行**（ONNX-FP32 vs ONNX-INT8） | Task 4 |
| 5 | **单次测量 + 阈值判定不可复现**：30 次输入的误差在 5e-05~1.5e-04 间波动，判据 1e-4 落在分布中间 → 判定有 33% 概率翻转 | Task 4 |
| 6 | mediapipe 1.0.1 的 `close()` **间歇性阻塞 42 秒**（`executor.shutdown(wait=True)` 无超时地等待原生 C 调用） | Task 2 |
| 7 | 延迟测量噪声约 **5%**（mean）、11.6%（p95）→ 对比结论必须显著大于噪声 | Task 2 |
